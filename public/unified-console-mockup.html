Product Architecture Audit

Do we really need "New Project", "Open Project", and File Menus?

Answering your question about whether users ever revisit screening projects after exporting the EDL.

❌ Old Desktop Paradigm
  • • "File ▾ New Project" forces the user to name a container before doing anything.
  • • "Open Project / Save / Saved" badges clutter the screen when working on video files.
  • • Popups ask "Discard unsaved changes?" even when all you did was preview a 5-second video.
  • • Two stacked header bars: one for the app, one for the room.
Result: High friction, modal popups, and confusion.
✓ Modern Session Paradigm
  • • File-Centric: The video file IS the session. You drop `Cut_v04.mov`, that's your cut.
  • • One Unified Top Bar: Seamless brand emblem, active cut name, mode switch, and export.
  • • Zero-Friction Revisit: Recent cuts are saved silently in local storage. Just click them.
  • • The Real Finish Line: The deliverable is the .EDL file. Once imported into DaVinci Resolve or Premiere, the editor works in the NLE, not in old project menus.
Result: Instant, cinema-grade flow. Like a whiteboard: screen, mark, export, done.

What We Can Safely Remove:

1. The Second Header Bar Eliminate the iframe's duplicate top bar. The main App header becomes the single bar for all modes.
2. "File ▾" Dropdown Menu Replace with direct actions: drop cut, recent cuts list, export EDL.
3. Technical Metadata in Screening Hide `24 FPS / 0 shots / 00:00:08:15` and `Saved` pill during screening. It belongs only in Studio.
4. "Discard Changes?" Prompts Everything auto-saves quietly into local storage. No modal traps.
