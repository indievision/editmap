# EDITMAP frontend and backend audit — 12 September 2026

## 1. Current state

Audited the current EDITMAP_GEMINI working tree, including existing uncommitted edits. No application code was changed. The application uses React 19, TypeScript, Vite, IndexedDB, and a Python FastAPI CV service. Current inference code uses YOLO, face recognition, and Demucs; Qwen/Ollama labels and setup instructions are partly obsolete.

Useful foundations already exist: explicit EDL/timecode tests, manual field protection, serialized autosaves with visible failures, reusable video sampling, timeline viewport filtering, and reviewable analysis states. Preserve these and the existing dark editor layout.

Verification:

- `npm test`: 71/71 passing.
- `npm run build`: fails with TS2322 at `src/analysis/cuts.ts:254`.
- Existing Playwright suite against a dedicated local Vite server: three failures at the shared New project entry step, then stopped at the configured audit limit; 21 tests did not run. All three failures are duplicate accessible-name selectors, not demonstrated scan failures.
- Separate Chrome smoke check disambiguated that button, created a project, linked `fixtures/test-film.mp4`, and imported `fixtures/cuts-24.edl`. No page JavaScript errors. Inspected a 1440×1000 screenshot.
- Small in-memory probes reproduced backup field loss, unstable cluster identities, and misleading outputs on unavailable recognition models.
- The CV service was not reachable at port 8000, including a check outside the sandbox. No real model accuracy or throughput benchmark was run. Python probes used simulated engine failure and synthetic embeddings, without model downloads.

## 2. Problems and smallest proposed fixes

### P1 — Backup restore silently loses analysis

`src/storage/backup.ts:49–110` reconstructs a subset of the project schema. It drops shot color/motion profiles, DME waveforms, cut eye-trace readings, analysis failures, and some suggestion fields. Export includes them, but import discards them. A round-trip probe returned false for preservation of DME, color, and motion data.

Fix: extend the existing validators to cover every persisted field, version migrations when necessary, and test a fully populated project through export/import. Include malformed new fields and older backups. Avoid blindly trusting arbitrary JSON.

### P1 — Rediscovery can change confirmed character identities

`server/cv_engine.py:575` assigns `char-1`, `char-2`, etc. from the current cluster order. `src/app/App.tsx:1589` replaces the cast wholesale but retains confirmed character analyses. Their IDs can now point at different people or missing cast members; custom names and references are replaced. Synthetic clusters with equal ranking swapped the identities behind `char-1` and `char-2` when input order changed.

Fix: give identities persistent IDs, reconcile new clusters against existing characters, and preserve confirmed/manual references. Keep unmatched clusters as proposed new characters. Make an intentional reset distinct from rediscovery and update all references atomically.

### P1 — Unavailable models are reported as successful empty detections

`server/cv_engine.py:134` catches YOLO failure and continues with no boxes and `uncertain=False`. The face-recognition fallback at lines 268–326 has no embeddings, and `analyze` returns `appearances=[]`, `unresolved=False` at line 370. Probes reproduced both outputs. Frontend logic can treat these as completed scans and exclude shots from character discovery.

Fix: return an explicit unavailable/failed state, preferably a structured 503 for a missing engine. Reserve empty detections for successful inference. Extend health reporting to expose engine readiness and selected model/version; preserve failed samples for retry.

### P1 — DME processing blocks the server and can attach results to the wrong project

`server/main.py:374–405` defines an async route but synchronously copies the upload, launches FFmpeg, and executes separation. This blocks that worker's event loop while processing. `src/app/App.tsx:829–850` commits the result without checking project ID or media generation; `src/analysis/dme.ts:24` has no abort signal or timeout. A project/media change during separation can receive a stale result.

Fix: first run blocking work in a bounded worker with a single-job limit. Add a project/media generation guard and cancellation to the client. For long films, use a local job ID with progress and cancellation rather than an indefinitely open request. A browser abort alone does not stop server computation. Bound decoded audio memory and process long media in chunks; current separation retains full input and output arrays.

### P1 — Production build is broken

`src/analysis/cuts.ts:248–254` produces `type: "skin"`, but `src/models/project.ts:204–211` excludes that literal from `FocalPoint`. TypeScript rejects the build even though unit tests pass.

Fix: decide whether skin is a separate persisted detection method; either support it consistently or map this heuristic to the existing saliency method. Verify readers/exporters and rerun the build. This mismatch is in the existing uncommitted working tree; the audit did not introduce it.

### P2 — Discovery hides failures and overstates temporal evidence

`src/analysis/characters.ts:338–375` silently skips non-OK face responses and logs other errors while still incrementing completed shots. Lines 425–451 then create ordinary analyses for every eligible shot, including failed samples, with no failure markers. A single midpoint face is expanded to the entire shot interval. This overstates the measured duration available to presence/gap calculations.

Fix: distinguish successful empty detections, failed samples, and detected faces. Store retryable failures and checkpoints; apply per-request deadlines. Represent midpoint evidence explicitly and mark any whole-shot extrapolation as an estimate, consistently with the targeted scan's sampling semantics.

### P2 — Scan entry points have inconsistent recovery semantics

`src/components/AllShotsAnalysis.tsx:619` shows character Resume only while the character scan is active; the running controller rejects another start, and the button disappears after stop. The full pipeline catches failed shots but announces all shots tagged at line 463. `src/app/App.tsx:899–1125` implements another pipeline that retains results locally until its final commit; cancellation can discard completed inference work.

Fix: show Resume when idle with pending work, count success/failure separately, and checkpoint completed results. Extract the shared queue and lifecycle logic incrementally into a hook rather than maintaining several divergent runners. Keep cut detection distinct from analysis of an existing EDL: the header currently asks permission to replace shots, but offers no direct preservation option in that flow.

### P2 — Shot-size rules are not a reliable framing classifier

`server/cv_engine.py:200–219` maps a detected person's height ratio directly to shot size: at least 85% becomes CU, 68% FS, 50% AS, and 35% MS. The human branch cannot produce ECU. Height of a clipped person box alone does not establish which body parts are in frame, so a nearly full-height full-body person can be labeled CU.

Fix: evaluate the current implementation on a representative labeled set with per-class results before selecting a replacement. Add body/face geometry evidence and uncertainty where insufficient. Keep human confirmation central; do not claim accuracy from API/schema tests or reuse benchmark results from another checkout/model.

### P2 — Local API access and resource limits are too broad

`server/main.py:23–30` permits every browser origin; line 376 accepts arbitrary local file paths for DME. Images, face arrays, embedding dimensions, thresholds, bin counts, and upload sizes lack practical bounds. Depending on browser local-network protections, an unrelated origin may reach and read responses from this localhost service; CORS alone should not be its trust boundary.

Fix: restrict origins to the supported app origins, validate a local session token, and remove the unused arbitrary-path API from browser access or restrict it to explicitly selected files. Bound request sizes, image dimensions, embedding shape/finite values, thresholds and jobs. Add FFmpeg deadlines and reject excessive work before allocation. Retain loopback binding.

### P2 — Tests and runtime provenance do not track the current application

`tests/browser/analysis.spec.ts:7` and `tests/browser/bulk-analysis.spec.ts:117` fail because New project matches both header and landing buttons. `tests/dme.test.ts:7` checks an in-memory object, not backup or IndexedDB persistence. No Python test files were present in the inspected backend/test inventory. `src/analysis/localModel.ts:9` says YOLO while `src/app/App.tsx:1576` stores Qwen as the result model. The scan footer and README also describe Qwen.

Fix: scope entry-step selectors, repair the existing suite, add backend API and failure-path tests, and share model provenance from service responses. Update AGENTS/README/setup to describe the actual backend, model readiness, FFmpeg requirement, and first-run model provisioning. Run typecheck/build alongside tests.

## 3. Proposed implementation order

1. Restore the build and browser test entry flow.
2. Fix backup completeness and stable character identity; add regression coverage before changing those paths.
3. Make backend failures explicit; repair discovery failure accounting, Resume, and stale DME result guards.
4. Move DME off the event loop, bound resources, and tighten localhost access.
5. Measure framing accuracy and long-film performance before model or concurrency changes.

Frontend refinement should preserve the current hierarchy. Prefer one compact service/readiness indicator, truthful completed/failed/review counts, and consistent scan controls. The inspected desktop view has two nested horizontally constrained tab rows; improve overflow discoverability and keyboard focus visibility before adding more controls. Treat this as a usability observation, not a completed accessibility audit.

For performance, decoder reuse and viewport filtering already exist. In the bulk framing loops, next-frame preparation begins after inference resolves, so genuine one-frame overlap is not currently achieved there. Measure decode, inference, UI commit, and save times on a representative film before reintroducing bounded lookahead. Profile playback updates before extracting large components or moving computation into workers.
